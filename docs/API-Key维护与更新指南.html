API Key 维护与更新指南

面向 Visionox-Whale 普通用户，无需手动编辑程序配置。

适用版本：1.28.0 及以上　|　更新日期：2026-07-13
最重要的保护：新 API 配置必须先检测成功才能保存。检测失败时，原来的 API Key 和地址不会被覆盖，软件仍保留原配置。

一、先判断应该从哪里操作

定期更换 API Key

模型和参数不变，只替换公司发放的新 Key。

使用“高级 → 设置”

更换 API 地址

公司调整了 Base URL，模型配置基本不变。

使用“高级 → 设置”

新电脑或模型升级

需要一次导入服务商、模型、Key 和模型参数。

使用“模型 → 导入 JSON”

二、在设置页更换 API Key 或地址

  1. 打开模型服务凭据

    进入 高级 → 设置 → 当前模型服务凭据。

  2. 选择正确的服务商

    在“服务商”下拉框中选择公司要求更新的服务。不要只看当前聊天使用的模型名称。

  3. 填写新配置

    更换 Key 时，把新 Key 粘贴到“替换”输入框。更换地址时，在“基础 URL”中填写完整的 http:// 或 https:// 地址。

    如果只改地址，可以不填写新 Key，软件会继续使用该服务商原来保存的 Key。

  4. 点击“检测 API”

    软件会使用刚填写的 Key 和地址进行一次临时通信测试，通常在 10 秒内返回结果。此时新配置还没有保存。

  5. 确认显示“API 检测通过”

    检测通过后会显示本次测试使用的模型，“保存凭据”按钮才会解锁。

  6. 点击“保存凭据”

    保存后新 Key 或地址正式生效。为了避免沿用旧检测结果，该服务商的模型会恢复为“待检测”状态。

  7. 再检测全部模型

    回到主界面，点击输入框下方的 模型 → 检测全部模型。通信通过的模型名称后会显示对号。

注意：“检测 API”通过后，如果再次修改 Key、地址或切换服务商，原检测结果会立即失效，必须重新点击“检测 API”。这是正常的防误操作设计。

三、在新电脑上通过 JSON 完整配置

  1. 取得完整配置文件

    当前完整配置文件是 providers-ful-new-0713.json。它包含可直接使用的服务商、模型、地址、Key 和模型参数，不需要普通用户手工修改。

  2. 选择 JSON

    在主界面点击 模型 → 选择 JSON 文件，选择准备好的配置。

  3. 阅读变更预览

    界面会列出将新增、更新、停用或删除的服务商和模型。发现服务商不对、模型数量异常或出现永久删除时，先不要确认。

  4. 确认导入并检测模型

    确认内容正确后导入，再点击“检测全部模型”。只有名称后出现对号的模型才表示当前电脑能够正常通信。

0713 完整配置导入后会发生什么

配置内容导入结果
外部 DeepSeek新增或完整更新 deepseek-official，保留 auto / flash / pro 切换和自动升级逻辑。
公司 Qwen新增或完整更新 local-qwen，使用唯一的 Qwen3.5-397B 模型，不显示 DeepSeek 的推理强度选择。
旧 local-deepseek通过 removeProviderIds 永久删除；预览中必须明确显示这项删除。
默认使用模型导入后选择 deepseek-official；完成“检测全部模型”后自动启用该服务商中第一个检测成功的模型。
Qwen 正式对话开启隐藏思考，固定传入 thinking_budget: 8192；程序不会按问题难度自动改值。
Qwen 通信检测通过 verificationRequestDefaults 临时关闭思考，只验证连接、Key 和模型 ID，不改变正式对话参数。
0713 文件使用 schema v2、importMode: "replace"。这里的 replace 是完整替换 JSON 中同 ID 的服务商，不会删除未列出的其他服务商；只有 removeProviderIds 明确列出的服务商会被删除。
JSON 分为两类：新电脑或需要同步完整模型清单时使用 0713 这类“完整配置”；日常只更换 Key 或地址使用设置页；单模型新增、改名、升级、停用或删除才使用 schema v3“维护配置”。

四、通过 JSON 清理过期模型

清理前先确认过期的是“整个服务商”还是“服务商中的一个模型”。优先停用旧模型；只有明确不再需要时才永久删除。

情况 A：使用 0713 完整配置移除 local-deepseek

providers-ful-new-0713.json 已在 removeProviderIds 中列出 local-deepseek，因此可以在更新 DeepSeek 和 Qwen 的同时清理该旧服务商，不需要额外导入删除文件。

预览是最终依据：0713 文件把 activeProviderId 设置为 deepseek-official，允许安全删除正在使用的旧服务商。确认导入前仍要检查预览中同时出现“更新服务商”和“永久删除 local-deepseek”。

情况 B：停用一个服务商中的旧模型

保留模型配置但不再让软件选择它，使用 disableModel。modelKey 必须使用原配置中的稳定 key，不能凭显示名称猜测。

{
  "schemaVersion": 3,
  "operations": [
    {
      "op": "disableModel",
      "providerId": "local-qwen",
      "modelKey": "company-qwen-old"
    }
  ]
}

如果一个服务商只有这一个模型，不能单独停用，否则该服务商将没有可用模型。此时应新增替代模型，或者像情况 A 一样移除整个过期服务商。

情况 C：按公司最新模型清单自动整理

当管理员提供该服务商当前全部在售模型时，使用 syncModels。清单中的模型会新增或更新，没有出现在清单中的旧模型会自动停用，不会永久删除。

上面的 Qwen 模型结构与 0713 完整配置一致。后续模型 ID、名称、上下文容量或原生请求参数变化时，让管理员或 AI 以最新完整配置为基准生成维护 JSON；普通用户只负责“选择文件 → 核对预览 → 确认导入 → 检测全部模型”。
requestDefaults 是正式对话参数；verificationRequestDefaults 只在“检测 API”和“检测全部模型”时递归覆盖正式参数。公司模型较慢或默认开启思考时，可在检测参数中关闭思考。以后模型升级通常只需更新 JSON 中的模型 ID、容量和原生参数，不需要重新安装软件。
agentPolicy 控制长文档的工具轮次、分页读取、工具结果预算和后台分批策略。Qwen 建议保留 documentPolicy 的 3000 / 8192 / 8 / 2 / true 配置；它适用于 PDF、Word、Excel、PPT、HTML、Markdown 等保存型整理任务。max_tokens 只控制单次模型输出，完整正文由宿主分批校验、失败块重试并最终组装，不要求模型一次生成全文。

五、如何判断操作是否成功

界面状态含义下一步
API 检测通过新 Key、地址和至少一个模型可以通信。点击“保存凭据”。
API 检测失败新配置未通过，旧配置没有被覆盖。检查服务商、Key、地址和网络后重新检测。
保存按钮不可用尚未检测，或检测后又修改了配置。重新点击“检测 API”。
模型名称后有对号该模型在最近一次完整检测中通信成功。可以开始对话。
模型名称后没有标识该模型尚未检测或配置变化后需要重测。点击“检测全部模型”。

六、常见问题

问题处理方法
检测超过 10 秒或提示超时确认已连接公司网络或 VPN，Base URL 可访问，然后重试。不要反复点击保存。
提示 Key 格式不正确重新复制完整 Key，不要带空格、换行或引号。
检测通过但保存失败检测结果可能已过期，或检测后字段发生变化。重新检测一次再立即保存。
保存后原来的对号消失这是正常现象。凭据变化后旧检测结果不再可信，需要“检测全部模型”。
不知道应该选择哪个服务商根据公司通知中的服务商名称确认；不确定时不要尝试覆盖多个服务商。
公司模型已经下架让管理员或 AI 生成维护 JSON，将旧模型停用；不要通过修改 API Key 来处理模型下架。
Qwen 简单问题也配置了 8192thinking_budget 是最大预算，不代表每次都会用满；程序会原样传递，简单问题通常由模型提前结束。

七、操作前最后检查

  • 我选择的是公司要求更新的服务商。
  • API Key 没有多余空格、换行或引号。
  • Base URL 包含完整的 http:// 或 https://。
  • 我先完成了“检测 API”，再点击“保存凭据”。
  • 保存后又执行了“检测全部模型”。
Visionox-Whale 用户操作文档。通常不需要重新安装或重启程序；设置保存后会自动更新模型服务连接。
