## 2. 本次发布审查已解决的问题

1. **发送意图误判**：`不要直接发送`、询问如何发送、分析/测试/引用发送流程不再被视为真实授权；“不用确认”本身不能授权发送。
2. **定时发送授权**：只检查用户保存的任务原始提示，不信任系统包装、检索内容或收到的企业消息。明确授权的安全消息可后台直发；有害、不确定和附件内容仍阻断或确认。
3. **主动退出竞态**：宿主先设置 shutdown 标志，初始启动线程和崩溃监控线程均不会在退出期间生成或重启 Node。
4. **首屏空白窗口**：隐藏 iframe 在 Dashboard 首次挂载后通过同源 ready 握手显示；12 秒未就绪时保留加载页并显示日志诊断入口。
5. **Tauri 2 壳桥兼容**：加载页同时支持 `__TAURI__.core.invoke` 和旧式 `__TAURI__.invoke`，刷新恢复、诊断和文件桥不再依赖错误入口。
6. **OfficeCLI 长操作超时**：OfficeCLI MCP 使用 180 秒请求超时，其他 MCP 保持默认 60 秒；超时后的安全恢复机制继续保留。
7. **DWS 完整开放性**：已知查询使用 `dws_read`，消息使用 `dws_write`，当前和未来其他业务命令使用逐次确认的 `dws_exec`，不存在业务命令白名单。
8. **纯文本路径粘贴卡顿**：已知的 `text/plain` Windows 路径直接写入输入框，不再等待 PowerShell/API；资源管理器文件复制优先调用 Rust 原生剪贴板。Edge 冒烟中的同一路径粘贴耗时为亚毫秒级。
9. **定时任务并发失败**：多个任务同时触发时改为单槽 FIFO 排队，同一任务重复触发合并；完成、取消或主对话空闲后立即续跑，重启补跑按原触发时间恢复顺序。
10. **发布日期校验过期**：发布脚本不再要求修改 vendored Reasonix 版本冒充当天日期，改为校验源码占位符和 Release 中实际注入的 `YYMMDD HH` 构建标记。
11. **第三方版本漂移**：Reasonix 来源清单和 NOTICE 已与实际包版本 `260713` 对齐，质量门禁新增强制比对。
12. **源码可移植性**：UI 粘贴性能测试移除本机用户名和项目绝对路径；运行时路径检查继续覆盖中文和空格目录。

## 6. 推荐发布顺序

1. 完成源码提交并推送，从干净 commit 执行唯一规范命令 `npm run bundle:nsis`。
2. 核对 `release-manifest.json` 的 commit、脏状态、两项验证状态和唯一规范安装包路径。
3. 用户使用该 NSIS 候选执行全新安装、覆盖升级和千条会话回归，并填写 `docs/RELEASE_CHECKLIST.md` 的人工结果。
4. 发布负责人确认第三方来源边界和回退方案。
5. 获得明确授权后再创建 tag、推送 tag、上传或对外发布。
