Visionox 语义索引与个人知识库

把工作区变成可语义检索的个人知识库，并在对话中自然调用

核心概念：语义索引会把工作区里的文本文件（代码、文档、笔记等）切成片段并生成向量。之后你只要用自然语言提问，模型就能“理解意思”并找到相关内容，而不需要你记住确切的关键词。

语义索引能做什么

  • 个人知识库：把 Markdown 笔记、技术文档、项目说明放进工作区，构建索引后直接向 AI 提问。
  • 代码语义检索：问“哪里处理登录失败”“数据加载逻辑在哪儿”，即使文件名里没有这些字也能定位。
  • 项目 onboarding：新人问“这个项目的入口文件是什么”“配置项怎么改”，模型基于索引回答。

第一步：配置工作区位置

语义索引的根目录就是当前工作区。默认位置：

  • Windows：C:\Users\<用户名>\visionox-workspace
  • macOS / Linux：~/visionox-workspace

如何更换工作区

  1. 在 Dashboard 中点击工作区选择器，选择或输入新的目录。
  2. 或在命令行启动时指定：visionox code D:\MyKnowledgeBase
  3. 修改后建议执行 /new 或重启会话，让新工作区生效。
提示：把工作区设成你专门存放知识资料的文件夹，就相当于给这个文件夹建了一个私有语义搜索引擎。

第二步：构建语义索引

方式 A：Dashboard 图形界面

  1. 打开 Dashboard →「高级」→「语义」面板。
  2. 配置 embedding 服务：默认使用本地 Ollama（如 nomic-embed-text），也可切换为 OpenAI 兼容 API。
  3. 点击「构建索引」或「重建索引」。
  4. 等待状态显示“索引已构建”。

方式 B：斜杠命令（可索引子目录）

  • /learn index ./docs —— 只索引 docs 目录
  • /learn index ./notes —— 只索引笔记目录
  • /learn ask 如何配置 MCP？ —— 基于已索引内容直接问答
依赖：使用 Ollama 时请确保本地服务已启动且模型已下载；使用 OpenAI 兼容服务时请配置好 baseUrl、apiKey 和模型名。

本地模型配置示例

如果你的局域网内已经部署了兼容 OpenAI 的 embedding 服务，可以按如下参数配置：

配置完成后点击「构建索引」，系统会向该地址发送 embedding 请求。

第三步：在对话中使用

索引构建完成后，直接在聊天里用自然语言提问即可，例如：

  • “这个项目里用户认证逻辑在哪里？”
  • “我们之前定义的 API 错误码规范是什么？”
  • “给我总结一下 docs/architecture.md 里的设计思路。”
用户提问 → 模型调用 semantic_search → 返回最相关的文本片段 → 模型组织语言回答
自动触发：模型会根据问题判断是否调用语义搜索，不需要你手动输入任何命令。

索引范围与排除项

索引什么

  • 当前工作区目录下的文本文件。
  • 代码、Markdown、TXT、JSON、YAML 等常见文本。
  • 默认按 60 行窗口、12 行重叠切分为 chunk 后生成 embedding。

默认排除

目录：

node_modules/ .git/ dist/ build/ target/ .venv/ __pycache__/ .visionox/

文件：

package-lock.json Cargo.lock yarn.lock .DS_Store

扩展名（二进制/媒体/压缩）：

.png .jpg .jpeg .gif .webp .woff .woff2 .ttf .zip .tar .gz

同时遵守 .gitignore 规则。

重要：语义索引不索引对话记录

范围说明：对话记录保存在 ~/.visionox/sessions/，不在工作区目录内，因此不会被语义索引覆盖。

查找历史对话的正确流程：

🧠 用户问“之前聊过 XXX” → list_sessions
列出历史会话 → read_session
读取目标会话内容

使用注意事项

  1. 按工作区隔离：每个工作区有独立索引。切换工作区后需要重新构建索引。
  2. 不会自动更新：工作区文件修改后，需要手动「重建索引」或「增量索引」，否则模型可能基于旧内容回答。
  3. 需要 embedding 服务：本地 Ollama 或 OpenAI 兼容 API 必须可用，否则无法生成向量。
  4. 隐私性好：使用 Ollama 时，embedding 计算和索引文件全部保存在本地。
  5. 可只索引子目录：不需要把整个工作区都索引，用 /learn index <dir> 按需构建。

常见误区

❌ 误区：semantic_search 能搜到所有跟我聊过的东西

✅ 事实：它只索引工作区目录下的文本文件。对话记录存在别处，需要 list_sessions / read_session。

❌ 误区：semantic_search 搜不到 = 不存在

✅ 事实：可能是索引范围未覆盖、索引未更新，或内容在对话记录里。先确认目标内容属于哪个范围。
