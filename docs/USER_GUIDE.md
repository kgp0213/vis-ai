# Visionox-Whale 用户使用指南

> 适用版本：Visionox-Whale 1.28.0

第一次使用时，建议先阅读[快速上手](快速上手.md)。

---

## 工作空间切换

主界面输入框下方的“工作空间”菜单会显示当前目录、等待在下一次新对话生效的目录，以及最多 10 个最近使用的工作空间。最近列表保存在 `~/.visionox/config.json`，清理 WebView2 或浏览器缓存不会丢失；已经不存在的目录会自动从列表中忽略。

选择“浏览其他目录”会在桌面端打开系统目录选择器；浏览器调试环境则使用手动路径输入。选择工作空间不会打断当前对话，在下一次新建对话时完成切换。历史条目右侧的“×”只移除最近记录，不删除目录，也不会切换当前工作空间。

## 一、记忆系统使用

Visionox 提供四类记忆，让 AI 记住你的偏好、项目事实和临时上下文。记忆按范围和生命周期分层，不同工作模式下的记忆互不干扰。

### 1.1 记忆类型速览

| 记忆类型 | 何时使用 | 生命周期 |
|----------|----------|----------|
| **会话记忆** | 临时记住当前讨论的上下文 | 当前对话（`/new` 清除） |
| **模式偏好记忆** | 让当前模式记住工作习惯 | 跨会话，仅当前模式可见 |
| **全局记忆** | 让 AI 始终记住身份/偏好 | 跨所有会话和项目 |
| **项目记忆** | 记住当前项目的关键信息 | 跨会话，仅当前项目可见 |

### 1.2 记忆注入层级

每次 `/new` 重建上下文时，按以下顺序加载 9 层内容：

| 层 | 来源 | 用途 |
|----|------|------|
| L0 Soul | `~/.visionox/soul.md` | AI 身份与行为准则 |
| L1 Project | 项目根目录 `AGENTS.md`/`AGENT.md`/`agent.md`/`CLAUDE.md`/`claude.md`/`visionox.md` | 工作区说明文件（自动注入，单文件≤8000字符，合计≤12000字符） |
| L2 Mode | `config.json` -> `modes[mode].prompt` | 场景行为指令 |
| L3 Mode Memory | `~/.visionox/mode-memory/{mode}.json` | 当前场景的长期记忆与偏好（前 8 条高优先级注入） |
| L4 ECC Rules | `~/.visionox/rules/ecc/{lang}/` | 编码规范（mode 控制） |
| L5 Custom Rules | `~/.visionox/rules/*.md` | 用户自定义规则 |
| L6 Skills | `~/.visionox/skills/*/SKILL.md` | 领域技术能力索引（按模式 ⭐ 标注推荐） |
| L7 Persistent | `~/.visionox/memory/*/MEMORY.md` | 跨会话持久记忆索引；高优先级额外注入全文 |
| L8 Session | `remember_session` 工具（内存） | 当前对话临时上下文（每条≤2000字符，总量≤6000字符） |

> `REASONIX.md` 不参与项目记忆读取。工作模式切换后立即重建 loop 生效，无需 `/new`。

### 1.3 对话中存储记忆

| 目标 | 推荐说法 | 存储位置 |
|------|----------|----------|
| 跨项目长期事实 | `请长期记住：我的常用称呼是张三` | `~/.visionox/memory/global/` |
| 当前项目专属知识 | `请长期记住到当前项目记忆：发布流程是先打 tag 再构建` | `~/.visionox/memory/<project-hash>/` |
| 当前场景回答习惯 | `请在编程场景下长期记住：我习惯用 Vite + pnpm 构建项目` | `~/.visionox/mode-memory/{mode}.json` |
| 临时上下文 | `请临时记住：本轮先按方案 B 处理` | 进程内存 |

> **技巧**：避免只说"记一下这个"。如果内容要跨所有场景保留，使用"长期记住"；如果只应在某个工作场景保留，使用"在编程/办公/设计场景下长期记住"。

### 1.4 管理记忆

- **查看记忆**：在左侧「高级 → 记忆」集中查看全局、当前项目、工作场景、当前会话记忆和 AI 身份。列表会标明实际注入状态、优先级和诊断提示。
- **编辑和删除**：在记忆详情中结构化编辑或删除；长期记忆和工作场景记忆会先移入「回收站」，可继续预览、恢复或永久删除，也可清空回收站。回收站内容保留 30 天后自动清理；项目记忆必须打开原项目才能恢复，避免恢复到错误工作区。工作场景记忆还可移动、复制和批量启停或删除。
- **编辑 Soul**：在「AI 身份」中使用基础字段或高级原文编辑 AI 名称与 `soul.md`，可预览最终注入、恢复默认值或历史版本。Soul 不提供删除。
- **应用修改**：保存只保证内容写入磁盘。当页面提示当前上下文仍在使用旧记忆时，可在回答空闲时选择「立即应用到当前对话」；否则在下一次 `/new` 或上下文重建时生效。
- **项目规则文件**：项目根目录中的 `AGENTS.md`、`AGENT.md`、`agent.md`、`CLAUDE.md`、`claude.md` 和 `visionox.md` 会同时作为项目规则读取；`REASONIX.md` 不参与读取。
- **清理项目记忆**：「清除所有项目记忆」。

### 1.5 记忆优先级

AI 构建提示词时的注入优先级：

1. **高优先级**（标记为重要）→ 作为硬约束
2. **模式偏好记忆** → 按优先级排序，取前 8 条
3. **全局记忆** → 注入索引；高优先级条目额外注入全文
4. **项目记忆** → 注入索引；高优先级条目额外注入全文
5. **会话记忆** → 追加在末尾

## 二、工作模式

### 2.1 切换模式

在设置页的"工作场景"下拉框中选择，或通过 `/` 命令切换。切换后即时生效，无需 `/new`。

| 模式 | ID | 规则集 | 适合做什么 |
|------|-----|--------|-----------|
| 通用 | `general` | common | 日常问答、资料梳理、轻量排查 |
| 编程 | `coding` | common + rust + typescript + python | 代码阅读、修复、重构、测试、构建 |
| 办公 | `office` | common | 文档、表格、PDF、PPT、格式转换 |
| 设计 | `design` | common + web | 界面体验、前端布局、视觉风格 |

### 2.2 模式记忆隔离

每个模式有独立的记忆库，存在 `~/.visionox/mode-memory/` 下：

```
~/.visionox/mode-memory/
├── general.json       # 通用模式记忆
├── coding.json        # 编程模式记忆
├── office.json        # 办公模式记忆
└── design.json        # 设计模式记忆
```

在编程模式记住的内容不会跑到办公模式，反之亦然。

## 三、`/learn` 学习命令

### 3.1 技能萃取 `/learn skill`

把项目文档目录快速变成可复用 Skill：

```
/learn skill ./docs/api api-design-guide
```

Visionox 会扫描目录文本文件 → 调用 LLM 提炼规则 → 生成 `SKILL.md` → 安装到 `~/.visionox/skills/`。

### 3.2 项目 Onboarding `/learn project`

扫描当前 workspace，生成或更新项目记忆文件：

```
/learn project my-project
```

### 3.3 知识库索引与问答

```
/learn index ./docs          # 为目录构建语义索引
/learn ask 如何配置 MCP？     # 基于已索引内容问答
```

### 3.4 导师模式 `/learn tutor`

| 风格 | 行为 |
|------|------|
| `socratic` | 不直接给答案，通过提问引导 |
| `hint` | 提供提示，把复杂问题拆成小步骤 |
| `pair` | 结对编程伙伴，提出选项和权衡 |
| `off` | 关闭导师模式 |

导师模式为会话级，`/new` 后自动清除。

### 3.5 学习追踪 `/learn track`

```
/learn track on              # 主动学习模式：AI 穿插提问
/learn track senior          # 资深工程师模式：要求解释设计取舍
/learn track off             # 关闭学习模式
/learn track stats           # 查看概念库统计
/learn track due             # 今日到期概念
/learn track add <概念>       # 手动添加概念
/learn track review <概念> <again|hard|good|easy>  # 记录复习结果
```

使用 SM-2 间隔重复算法调度复习，概念库存储在 `~/.visionox/learn-track.json`。

### 3.6 技能调用与管理 `/skill`

模型会根据任务自动选择技能，用户也可以手动指定：

```text
/skill list                         # 列出可用技能
/skill show brainstorming           # 查看技能说明
/skill brainstorming 设计导入流程   # 使用该技能处理后面的任务
@weather 查询明天北京天气            # 从输入框技能菜单选择后直接调用
```

输入框中的 `@技能名` 和 `/skill <名称> <任务>` 都是确定性调用：系统会直接读取该技能并执行，不依赖模型是否在详细技能目录中看到了它。聊天记录保留用户原始的 `@技能名` 文本。

对于“查询成都天气”“成都明天会下雨吗”等明确的天气查询，如果本机已安装 `weather` 技能，系统也会自动使用该技能。天气组件开发、Weather API 调试、技能文档讨论等技术请求不会触发自动路由；用户显式选择的 `@技能名` 始终优先。

`tavily-search` 随程序提供，并使用内置 Node.js 执行，不要求目标电脑另装 Python。首次调用 `@tavily-search` 时，如果尚未配置 Tavily API Key，输入框上方会显示本地凭据设置栏。填写后选择“保存并继续”，系统会把密钥写入 `~/.visionox/.env` 并自动继续原请求。密钥不会写入聊天记录，也不会发送给模型；接口只向界面返回“已配置/未配置”状态，不会回传密钥内容。若用户目录已经存在自行安装的同名技能，程序会保留该版本；“修复 Skill 环境”也不会强制覆盖它。

“高级 → 技能”中的全局技能如果标记为“随程序提供”，删除后会进入停用状态，重启不会自动恢复。点击“修复 Skill 环境”会重新启用并恢复所有随程序提供的技能。项目技能和用户自行创建的全局技能仍按普通删除处理。

## 四、OfficeCLI 办公

办公模式下，Visionox 默认使用内置 OfficeCLI 1.0.135，通过 MCP 处理 Word/Excel/PPT 操作。详细工作流见 [OfficeCLI 办公指南](OFFICECLI_GUIDE.md)。

### 支持的操作

- **Word (.docx)**：创建文档、读写内容、格式设置
- **Excel (.xlsx)**：创建表格、读写数据、公式计算
- **PowerPoint (.pptx)**：创建演示文稿、添加幻灯片

### 配置

启动时自动发现内置 `officecli.exe`。如需手动指定路径：

1. 打开 `%USERPROFILE%\.visionox\config.json`
2. 在 `mcp` 数组中添加：`"officecli=你的路径/officecli.exe mcp"`
3. 重启 Visionox

## 五、常用操作

### 5.1 剪贴板粘贴

- **图片/截图**：复制后按 `Ctrl+V` → 自动添加为附件
- **文件/文件夹**：从资源管理器复制后按 `Ctrl+V` → 自动贴入完整本地路径

### 5.2 模型切换

- **模型入口**：聊天输入区下方的「模型」按钮 → 选择 Provider 和具体模型
- **DeepSeek 预设**：选择外部 DeepSeek Provider 时可选 auto/flash/pro；内部单模型 Provider 不显示该预设
- **JSON 导入**：模型面板中选择 JSON 文件批量导入 Provider 配置
- **导入预览**：完整配置和维护配置都会先列出实际变更；停用模型仍可保留配置，永久删除会单独警告
- **凭据轮换**：进入「高级 → 设置 → 模型服务凭据」，先选择服务商，再输入新的 API Key 或 Base URL；必须“检测 API”通过后才能保存，检测失败不会覆盖旧配置
- **配置分工**：新电脑使用 schema v2 完整 JSON；单模型新增、改名、升级、停用或删除使用 schema v3 维护 JSON；模型推理参数仍只由 JSON 管理

### 5.3 会话管理

- **新建对话**：输入 `/new` 重置上下文
- **历史会话**：导航栏「会话」→ 搜索、预览、批量选择或继续历史会话
- **回收站**：删除操作先移入回收站，可预览、恢复或永久删除；过期内容按保留策略自动清理

### 5.4 编辑模式

聊天输入区附近可切换 `auto`、`yolo`、`admin`。旧配置中的 `review` 会兼容为 `auto`，不再单独显示。

## 七、会话报告

导航栏「任务」页面可创建"会话报告任务"，基于历史会话记录按每日、每周或自定义时间规则生成报告：

- **标题格式**：「{日期} Visionox {日报/周报}」（如 `2026-07-03 Visionox 日报`）
- **数据来源**：仅基于历史会话记录，不主动读取工作区文件
- **提示词分离**：默认提示词（随版本更新）+ 用户追加指令（跨升级保留）
- **导出**：支持导出为 Markdown 文件
- `/report daily|weekly|yearly [YYYY-MM-DD]` 也可触发报告生成

## 八、ECC 编码规范

集成了 ECC v2.0.0-rc.1 的 Skills 和 Rules：

| 组件 | 数量 | 位置 |
|------|------|------|
| Skills | 34+ 个编码类 | `~/.visionox/skills/` |
| Rules | 122 个文件、22 个规则包 | `~/.visionox/rules/ecc/{规则包}/` |
| Hooks | preTool/postTool | `launcher.mjs` 内置 |

每个工作场景独立保存启用的 ECC 规则。在“高级 → 设置 → 默认配置 → ECC 编码规范”中勾选规则包后会立即应用到当前场景；切换场景时会恢复该场景自己的选择。也可以在对话中使用：

- `/ecc`：查看当前场景启用的规则。
- `/ecc list`：列出全部内置规则包。
- `/ecc add golang`：为当前场景启用规则包（`go` 可作为 `golang` 的别名）。
- `/ecc remove golang`：为当前场景停用规则包。

`~/.visionox/rules/ecc/` 是由应用托管的内置资源，应用升级时同名规则会随内置版本更新。用户自己的长期规则应保存为 `~/.visionox/rules/*.md`，该目录不会被 ECC 部署覆盖，并始终作为自定义规则加载。

## 九、常见问题

**Q：切换工作模式后为什么感觉没变化？**
A：切换模式后系统会立即重建 loop，新模式的提示词、技能和规则即时生效。如果感觉没变化，可能是当前对话仍在使用旧上下文，输入 `/new` 开启新对话即可完全刷新。

**Q：编程模式记住的内容切换到通用模式能用吗？**
A：不能。模式偏好记忆按模式隔离。如需跨模式生效，请使用全局记忆。

**Q：记忆内容有长度限制吗？**
A：每个场景最多保存 60 条模式偏好记忆，提示词选择前 8 条启用记忆。会话记忆单条上限 2000 字符、总量上限 6000 字符。全局和项目长期记忆按完整条目控制提示词预算，不会从条目中间截断。

**Q：如何关闭记忆功能？**
A：设置环境变量 `VISIONOX_MEMORY=off` 可禁用所有记忆注入。
